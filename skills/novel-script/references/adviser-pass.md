# 顾问软审执行细则（Step 3.5 用）

由 Claude 执行（不是脚本——脚本零依赖调不了模型）。输入 `script.json` + `outline.json` + `cast.json`（缺 cast 照审，纯从剧本推断角色动机），输出 `<剧名>-script-adviser.txt`。

**审的范围**：默认审 **script.json 里实际已写的集**（validate 钩子会提示"已写 N 集"）——剧本分批写，每批 validate 通过后就审这批，及时止损。不要假设"全集都在"、按全集审。用户明确说"全集整体审"才跨全部集，且此时仅当参考、慎改（接近定稿，改了要重跑下游）。

**输出位置**：`<剧名>-script-adviser.txt` 存 **script.json 同级目录**（跟 `<剧名>-script.json` 放一起，用户好找）。

## 你的角色：独立审稿人，不是作者

**你不是写这个剧本的人，是拿到陌生剧本的挑剔审稿人。** 立场是挑毛病，不是护剧本。能开子代理就开（不继承写作上下文）；开不了就人格切换，写死这句"你不是作者，是审稿人"。

## 五个角度（每角度都要审，但别硬凑）

| 角度 | 审什么 | 典型问题 |
|------|--------|---------|
| 人物动机 | 角色为什么这么做，合理吗 | 行为突变零铺垫 / 工具人 |
| 情感铺垫 | 情绪/反转前埋线够不够 | 强行煽情 / 反转无预兆 |
| 逻辑漏洞 | 因果链、时间线、身份一致 | 时间对不上 / 死了又活 / 能力乱用 |
| 伏笔缺失 | 埋没收、该埋没埋 | 开场道具永不回收 / 后需的线前没埋 |
| 爽感节奏 | 这集爽不爽、爆点够不够、节奏拖没拖 | 铺垫拖太长 / 爆点不够狠 / 全集平 |

## 边界（不报这些）

- **硬门已查的**（时长超±15%、单句>35字、说话人非法、钩子没落纸、爽点没认领……）——那是 validate 的活，你聚焦软伤
- 没有证据支撑的泛泛之谈（"剧情可以更紧凑"）——不算建议
- 纯格式问题——不管

## 证据规则（每条建议必须过这一关）

**局部问题**（指到具体某拍）：必须带原文证据——从 `script.json` 里抄那一拍的内容。

**整体性问题**（跨多拍/多集）：允许没有单句原文，但必须：
1. 指明范围（哪几集 / 哪几拍）
2. **至少给 1 个具体落点**（比如"第2集第5-8拍连续4拍寒暄"）——防胡诌

**没证据/没落点的建议，删掉。** 这是硬规矩。

## 定位粒度

- 用 `第X集 · 第Y拍`（拍 = 该集 scenes 里 flow 数组的顺序号，从 1 数）
- 定位到场景 + 拍：`第2集 · 场2 · 第14拍`
- 后面跟一句内容片段（让人不用翻 JSON 也能对上号）

## 归属层（每条标问题根源在哪）

- `归属：剧本` → 剧本层问题，改 script.json
- `归属：outline` → 上游大纲问题（如"这集大纲没标爽点"）——**提示回 outline 改，不在剧本层硬改**
- `归属：characters` → 角色卡问题（如角色动机单薄）——提示回 characters 改

标错归属没关系，用户会判断；但别把上游问题当成剧本问题硬改。

## 分级

- 🔴 必须看：影响主线/人设/爽感，不修会出戏
- 🟡 建议：能更好，不改也不崩
- ⚪ 可选：吹毛求疵

## 输出格式（txt）

```
《剧名》剧本顾问审 · N 条建议
━━━━━━━━━━━━━━━━━
🎯 最值得改的 3 条（top 3）
   🔴 角度｜第X集·场Y·第Z拍｜归属：剧本
   证据：「原文」
   问题：一句话说清
   建议：具体怎么改
   ⚠️ 影响：对时长/硬门的影响（如 +30 秒需砍戏）
   ...
━━━━━━━━━━━━━━━━━
其余建议（附后，按需看）
   ⚪ ...
...
🎯 如果只能改 1 处 → 改第 1 条
结尾：一句话整体印象（这剧本成色如何、最弱的一环在哪）
```

数量：每角度 2-5 条，总量 ≤ 15。宁缺毋滥。

## 闭环（执行者是我）

```
出建议 → 用户挑"改哪条"（最多 3 条）
  ├─ 归属剧本 → 我改 script.json（定向补丁，只改那几处，其余不动——不是重跑）
  ├─ 归属 outline/characters → 提示回上游改，改完重跑剧本
  └─ 改完 → 重新 validate → 下游 storyboard 相关段重跑
```

- **收敛**：每轮最多改 3 条，改完这轮结束；用户主动说"再审"才再审
- 开头明说代价："采纳建议可能触发下游重跑"
- 软审建议永远不进 validate（不卡门），只当参考
