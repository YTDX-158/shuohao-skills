# 分镜图提示词规范（出图包内 02_分镜图提示词.txt）

由 `novel-assets.mjs run` 自动生成，打进 `<剧名>-出图包.zip`。GPT 在第 1 步生成完设定图后读这份，生成分镜图（关键帧）。**参考来源是 GPT 自己刚生成的设定图（记忆引用），不再要求用户上传。**

## 结构

```
你是一名美术总监，为短剧《X》生成全部 36 张分镜图（关键帧）。
【统一要求】  ← 9:16 竖屏 + 引用上面生成的设定图 + 顺序生成
【每镜提示词】
  【E01-01 第01镜】
  命名：E01-01_f1.png
  引用设定图：【城市灾难蒙太奇】【裂口女】
  画面：<frame 提示词>
  ...
```

## 关键规则

1. **比例取 `--ratio` 参数**（默认 9:16）——分镜图是视频帧，必须跟视频比例一致。**方向词按比例推导**（`9:16`→竖屏、`16:9`→横屏、其他不带方向词），不写死"竖屏"（否则 16:9 会输出"16:9（竖屏）"自相矛盾）
2. **参考来源 = GPT 记忆**：设定图已由 GPT 在第 1 步生成并记住，分镜图任务强调"引用你上面生成的设定图，不要另造形象"。**不生成参考图清单、不要求用户上传**
3. **逐镜 A 方案绑定前缀**：`引用设定图：【场景】【角色】【道具】`——GPT 照着引用刚生成的那张设定图，不猜
   - 场景从 `sceneImage`（`images/<场景名>-sheet.png`）解析
   - 角色/道具从 `binds` 解析，脚本对 cast 别名做兜底（如 binds 写"小红"能查到"红色纸人"）
4. **画面提示词用 `frame`**（英文构图描述），不是 `seedancePrompt`（中文视频提示词）
5. **命名扁平 + 段内计数**：`<段号>_f<段内镜号>.png`（如 `E01-01_f1.png`，段内从 1 数、无前导零，与上游 exportPack 的 `f${i+1}` 对账）——不用它建目录结构，zip 内目录不可靠
6. **打包要求**：交付 zip 内文件名照给，不改

## 参考绑定解析逻辑（脚本内）

- `binds` 里的名字可能是正式名（`裂口女`）或别名（`小红`），脚本先查 cast 的 `name`+`aliases` 映射，再查 art 的场景/道具名，最后兜底拆 `-` 前缀
- `sceneImage` 直接取文件名去 `-sheet.png` 后缀
- 拆不出的绑定不输出（不阻断生成），但会丢在警告里

## 为什么要逐镜绑定（A 方案）

GPT 记得住所有设定图形象，但**不逐镜标注的话它会猜**——可能把林风的形象用到楚楚的镜头。逐镜写 `引用设定图：【...】` 让 GPT 明确"这镜用哪张刚生成的设定图"，是分镜图一致性的关键保障。

## 比例冲突的坑（同设定图）

分镜图任务写 9:16，但 `frame` 提示词本身不含比例——GPT 会按任务文本的 9:16 出竖版关键帧。**不要**把 `frame` 原文里的任何横版词（如 wide landscape）再补进去，会打架。

## 说明.txt 的衔接

分镜图任务文本不自己说"先记住设定图"——那在第 1 步的 `说明.txt` 和 `01_设定图提示词.txt` 里。分镜图任务只负责"引用"。
